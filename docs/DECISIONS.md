# Decisions

Every significant choice on this project, with the alternatives it beat and why. A
decision is **superseded, never deleted** — the old row stays, marked, so the history
of thinking is kept. Phases, not dates.

| # | Phase | Decision | Alternative(s) rejected | Why | Status |
|---|-------|----------|-------------------------|-----|--------|
| D-1 | Setup | One **public** repo for the capstone, with a `docs/` folder that is also public | Two-repo split (public code + private docs), as used on the VRE project | Nothing here is secret or under formal embargo, and the docs (decisions, reports, model card) are exactly what demonstrate judgement to a reviewer — hiding them works against a portfolio. The two-repo split pays off only when there is genuinely private material. | Active |
| D-2 | 1 | Dataset = a **10-class subset of UCF101** (~500 clips), streamed with `remotezip` from the Google Cloud mirror `storage.googleapis.com/thumos14_files/UCF101_videos.zip` | (a) Full UCF101 (101 classes, ~6.5 GB); (b) HMDB51; (c) Kaggle UCF101; (d) official crcv.ucf.edu download | Full UCF101 is too heavy for a Colab T4 in storage and time. HMDB51 is smaller but harder (more camera motion), distracting from the pipeline lesson. Kaggle needs an API token (friction). The official source has been unreliable for years. `remotezip` reads the zip index over HTTP and pulls only the ~500 files we need, so we never download the 6.5 GB archive, from a rock-solid GCS host. | **Superseded by D-7** |
| D-7 | 1 | Dataset = a **pre-made 9-class UCF101 subset** downloaded from Hugging Face (`ambarishnarayan/UCF_101_Subset`, a 214 MB `tar.gz`, 457 clips, pre-split train/val/test). Classes: BenchPress, BreastStroke, CleanAndJerk, Diving, FrontCrawl, JumpingJack, Lunges, PullUps, PushUps | (a) Keep D-2's GCS `remotezip` plan; (b) download full UCF101 (HF `quchenyuan/UCF101-ZIP`) and cut a subset ourselves; (c) Kaggle | The D-2 GCS mirror now returns **403 Forbidden** (the `thumos14_files` bucket was locked down), breaking the stream at the first request. The HF subset is small (214 MB, so downloading it whole is cheap), reliable, versioned, already split, and lands in the exact `train/val/test/<class>/*.avi` layout the pipeline wants. It is 9 classes rather than 10 — accepted, since the class count is incidental to the project. Pulling the full 6.5 GB set just to cut a subset would be far slower for no benefit. | Active |
| D-3 | 2 | Frame features from a **frozen, pretrained ResNet18** | (a) Train a CNN from scratch; (b) fine-tune the full ResNet end-to-end with the temporal model | ~300 training clips is far too little to train a CNN from scratch, and end-to-end fine-tuning of a video model is compute-heavy and prone to overfitting on this data. A frozen ImageNet backbone is the transfer-learning lesson from Group 2, and gives strong per-frame features for free. | Active |
| D-4 | 2 | **Extract frame features once and cache them to Drive**; train the temporal model on the cached tensors | Decode video and run the CNN every epoch | Video decoding plus a CNN forward pass is the slow part by far; doing it per epoch would make training impractical on Colab. Caching makes training fast, cheap, and resumable after a timeout — the persistence lesson applied from the start. | Active |
| D-5 | 2 | **16 frames per clip**, evenly spaced across the clip | (a) All frames (variable length); (b) fewer frames (e.g. 8) | All-frames gives variable-length sequences and much heavier compute for little gain on short clips. 16 evenly-spaced frames capture the action's temporal structure at a fixed, batchable length; 8 risked dropping too much motion detail. May be revisited if accuracy is frame-starved. | Active |
| D-6 | 3 | Temporal model = **BiLSTM + attention pooling**, with mean- and last-state pooling as baselines to compare against | (a) Mean pooling only; (b) last-hidden-state only; (c) a Transformer encoder | The point is to measure what attention buys, so the baselines are kept as explicit comparisons rather than discarded. A Transformer was already studied on the sensor-HAR project; BiLSTM + attention keeps this capstone focused and directly reuses the Group 3 + Group 4 components. A Transformer variant is a possible extension. | Active |
